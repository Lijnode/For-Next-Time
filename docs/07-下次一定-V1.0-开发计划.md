# 1. 开发目标

V1.0 的目标不是把所有可能的功能都做完，而是完整跑通：

```text
注册 / 登录
→ 留下一条内容
→ 长期积累
→ 搜索
→ 找到
→ 一键复制
→ 最近使用
```

开发阶段始终围绕：

> 先留下 → 找得到 → 用得上

推进。

---

# 2. 开发总原则

本项目开发必须遵循：

```text
设计已评审
→ 再编码
```

以及：

```text
一次只做一个完整的小闭环
→ 做完
→ 自测
→ 联调
→ 验收
→ 再进入下一项
```

禁止：

- 同时铺开大量未完成模块
- 先写一堆空 Controller / Service / 页面占位
- 一次性生成整个项目后再统一修 Bug
- 未经设计评审擅自改数据库
- 未经设计评审擅自改 API
- 未经设计评审扩大 V1.0 范围

# 28. 每个功能的标准开发循环

每个功能都按照：

```text
1. 阅读对应文档
2. 定位相关现有代码
3. 确认 DB / API 是否已设计
4. 后端实现
5. 后端测试
6. PC 实现
7. H5 实现
8. 联调
9. 构建检查
10. 验收
11. 提交 Git
```

并不是所有功能都必须机械地“后端 → PC → H5”。

如果是纯前端功能，可以只改前端。

但只要涉及共享业务：

> 两端最终都必须联调。

# 29. Coding Agent 单次任务建议粒度

推荐一次任务：

```text
完成一个完整功能
```

例如：

> 完成注册登录后端 + PC + H5 + 联调。

或者：

> 完成内容新增完整链路。

不要一次要求：

> “把 V1 全部写完”。

原因：

- 难验收
- 容易偏离文档
- Bug 难定位
- Agent 容易过度生成
